같은 클로드라도 문(門)이 세 개입니다. 일의 성격에 맞는 문으로 들어가야 결과도 좋고 크레딧도 아낍니다.

세 개의 문한눈 비교표판정 퀴즈넘어가는 법크레딧 절약 수칙시작하기·모드·모델지침프로젝트스킬커넥터·MCP딥 리서치
선택 기준 한 줄

질문·대화·기본 활용은 채팅(Chat)
문서·파일·업무 자동화는 코워크(Cowork)
프로그램 개발은 코드(Code)

※ 채팅에서도 PDF·문서 생성이 가능합니다. 어느 하나만 되는 것이 아니라, 주로 하는 일에 맞는 곳을 고르면 결과와 비용이 가장 효율적이라는 뜻입니다.

🔰 먼저 안심하세요 — 셋은 "순서"가 아닙니다

대부분의 일은 채팅만으로 충분하고, 계속 채팅만 써도 됩니다. 단계를 밟아 올라가야 하는 교육 과정이 아니라, 필요할 때만 문을 바꾸는 것입니다.

코워크로 넘어가는 경우는 딱 이럴 때입니다 — 내 컴퓨터의 파일들을 직접 정리·수정시키고 싶을 때, 여러 자료를 모아 완성 문서를 만들 때, 같은 작업을 매일 자동으로 반복시키고 싶을 때.

코드로 넘어가는 경우는 하나뿐입니다 — 프로그램·웹서비스를 만들 때.

4. 채팅에서 제작(코워크·코드)으로 넘어가는 법

4-1. 막막할 때 프롬프트 — 이 두 문장이면 충분

정교한 프롬프트가 없어도 됩니다. 아래처럼 평범하게 물으면 AI가 알아서 정리하고 다음 단계를 안내합니다.

지금까지 한 것을 정리해줘. 나는 이제 무엇을 해야 하지?
이 작업을 코워크(또는 코드)에서 이어서 하고 싶어. 어떻게 하면 되는지 알려주고, 넘겨줄 문서를 만들어줘.

4-2. 구체적 프롬프트 — 3단계

4-1의 질문을 조금 더 정확하게 만든 절차입니다. 익숙해지면 이쪽이 결과가 더 좋습니다.

1단계

채팅에서 "인수인계 문서"를 만들게 한다.

긴 대화를 통째로 옮길 필요가 없습니다. 결론만 압축시키는 것이 핵심이자 크레딧 절약 포인트입니다.
지금까지의 논의를 다른 작업 세션에 넘길 인수인계 문서로 정리해줘.
① 한 줄 정의(무엇을 만드는가) ② 문제·배경 ③ 결정된 원칙 ④ 자산 목록(파일·링크) ⑤ 다음 할 일 ⑥ 첫 지시
— 이 여섯 항목으로, 복사해서 바로 쓸 수 있게 써줘.
2단계

코워크(또는 코드)를 새로 열고, 첫 메시지에 붙여넣는다.

인수인계 문서 + 관련 파일(또는 아티팩트 링크)을 함께 주면 이어서 작업됩니다. 아티팩트는 링크만 붙여도 내용을 읽어 이어받습니다.
{인수인계} 아래는 채팅에서 정리한 작업 지시서다. 이 내용대로 제작을 시작해줘.
(여기에 1단계에서 받은 인수인계 문서 붙여넣기)
(관련 파일 첨부 또는 아티팩트 링크 붙여넣기)
3단계

제작이 끝나면 결과 링크·파일만 보관하고 대화는 닫는다.

다음 수정 때는 새 대화에서 결과 링크나 파일만 다시 주면 됩니다. 이렇게 하면 대화가 무한정 길어지는 것을 막을 수 있습니다.

4-3. 인수인계 문서 (Handoff)에는 무엇을 담나 — 6항목

인수인계 문서는 "새 세션이 아무것도 모른다"는 전제로 씁니다. 아래 6항목이 표준 구성입니다.

항목내용
① 한 줄 정의이 프로젝트가 무엇인지 한 문장 (예: "소상공인용 AI 홍보글 학습 플랫폼")
② 문제·배경왜 만드는지, 해결하려는 문제 정의
③ 결정된 원칙지금까지 확정한 규칙 전부 (디자인 규칙, 용어, 금지사항 등 — 가장 중요, 빠뜨리면 새 세션이 다시 물어봄)
④ 자산 목록지금까지 만든 파일·아티팩트 링크·참고 사이트 주소
⑤ 다음 할 일이어서 할 작업을 우선순위대로
⑥ 첫 지시새 세션이 받자마자 실행할 첫 작업 + "모르면 나에게 역질문하라"는 한 줄

직접 쓸 필요 없습니다 — 기존 대화에서 "위 6항목 구성으로 인수인계 문서를 만들어줘"라고 시키면 AI가 대화 전체를 요약해 만들어 줍니다.

4-4. 코워크(Cowork)로 넘어갈 때

1단계

코워크(Cowork)를 연다.

클로드 데스크톱 앱에서 코워크 메뉴를 열고 새 작업을 시작합니다.
2단계

(필요하면) 내 컴퓨터의 작업 폴더를 연결한다.

내 파일을 읽거나 고치는 작업이면 폴더를 지정해 접근을 허용합니다. 새 문서·웹페이지만 만드는 작업이면 건너뛰어도 됩니다.
3단계

첫 메시지에 이관 프롬프트 + 인수인계 문서 + 자료를 붙여넣는다.

관련 파일을 첨부하거나 아티팩트(웹페이지) 링크를 붙이면 코워크가 내용을 읽고 이어서 작업합니다.
{인수인계} 아래는 채팅에서 정리한 작업 지시서다. 이 내용대로 제작을 시작해줘.
필요한 파일이 있으면 나에게 요청하고, 결정이 필요한 것은 역질문해줘.
(인수인계 문서 붙여넣기)
(관련 파일 첨부 또는 아티팩트 링크 붙여넣기)
핵심

결과물은 파일이나 아티팩트(웹페이지)로 남기게 하세요.

코워크의 결과물은 내 폴더의 파일 또는 아티팩트 링크로 남습니다. 다음 수정 때는 새 대화에서 그 결과 링크나 파일만 다시 주면 이어집니다.

4-5. 코드(Code)로 넘어갈 때 — CLAUDE.md

1단계

코드(Code)를 연다.

클로드 데스크톱 앱의 Code 메뉴를 열거나, 개발 환경(터미널)에서 Claude Code를 실행합니다. 처음이라면 데스크톱 앱의 Code 메뉴가 가장 쉽습니다.
2단계

프로젝트 폴더를 만들고 지정한다.

코드는 폴더 단위로 일합니다. 새 폴더(예: k-bridge)를 하나 만들어 작업 폴더로 지정하세요. 이 폴더가 프로젝트의 집이 됩니다.
3단계

첫 메시지에 아래 이관 프롬프트 + 인수인계 문서를 붙여넣는다.

1~3단계(위 정식 절차)에서 만든 인수인계 문서를 함께 붙이면 됩니다. 그다음은 코드가 제안하는 폴더 구조·작업 목록을 검토해 승인하면 개발이 시작됩니다.
핵심

코드에는 CLAUDE.md라는 "상주 기억 파일"이 있습니다.

프로젝트 폴더에 CLAUDE.md 이름으로 저장된 문서는 그 폴더의 모든 작업 세션이 매번 자동으로 읽습니다. 인수인계 문서를 CLAUDE.md로 저장하게 하면, 대화가 바뀌어도 결정사항이 계속 유지됩니다 — 사실상 대화를 "이식"하는 효과입니다.
{인수인계} 아래 문서는 이전 작업에서 완성한 프로젝트 인수인계 문서다.
1. 이 문서를 CLAUDE.md로 저장해줘.
2. 문서의 "다음 할 일" 순서대로 개발을 시작하되, 시작 전에 (1)폴더 구조 (2)기술 선택 (3)세부 작업 목록을 먼저 제안하고 내 승인을 받아줘.
3. 결정이 필요하거나 모르는 것은 진행하지 말고 나에게 역질문해줘.
(이 아래에 인수인계 문서 전체 붙여넣기)

포인트 세 가지 — CLAUDE.md 저장 지시(기억 이식), 승인 게이트(제멋대로 진행 방지), 역질문 지시(모르면 묻게 하기). 이 세 줄이 코드 이관의 안전장치입니다.

7. 지침 (Instructions) — 나를 한 번만 설명해 두기

지침 = 매번 설명하지 않아도 되게 미리 적어 두는 행동 규칙

"나는 어떤 사람이고, 이렇게 답해 달라"를 한 번 저장해 두면, 이후 모든 대화에서 그 규칙대로 답합니다.말투·답변 형식·자주 하는 요청이 들어갑니다.

설정 위치 — 왼쪽 아래 이름 → 설정 → 일반 → "Claude 지침". (메뉴 이름은 바뀔 수 있습니다.)

실습 — 지침을 AI가 대신 만들게 하기. 무엇을 적어야 할지 모르면, 질문부터 하게 합니다.

내가 앞으로 너와 일할 때 쓸 "지침(개인 맞춤 설정)"을 만들려고 해.
내가 주로 하는 일, 좋아하는 말투와 답변 형식, 반복해서 부탁하는 일을 네가 충분히 파악하는 것이 목표야.
한 번에 하나씩, 대답하기 쉬운 질문으로 물어봐 줘. 내 답을 바탕으로 다음 질문을 더 구체적으로 이어가고,
정보가 충분히 모였다고 판단되면 그때 "지침 초안"을 정리해서 보여줘.

답을 다 한 뒤 나온 "지침 초안"을 그대로 설정에 붙여 넣으면 됩니다. 마음에 안 드는 줄은 지웁니다.

9. 스킬 (Skill) — 반복 업무를 한 번 학습시킨 업무 매뉴얼

스킬 = 무엇이든 하는 AI를 "내 업무에 꼭 맞게" 특화시키는 폴더

AI는 코딩·문서·수학까지 다 할 줄 압니다. 그래서 가끔 내 일에는 엉뚱하게 답합니다. 스킬은 내 업무 절차와 자료를 한 번 담아 두고, 필요할 때만 꺼내 쓰게 하는 방법입니다.

스킬이 없으면 매번 처음부터 설명하고 결과가 들쭉날쭉합니다. 스킬이 있으면 내용만 바꿔 넣으면 같은 품질로 완성됩니다.

9-1. 왜 자료를 통째로 주지 않고 스킬로 나누나 — 컨텍스트 창 (Context Window)

AI가 한 번에 읽고 참고하는 정보의 양(컨텍스트 창)에는 한계가 있습니다. 모든 설명서를 늘 펼쳐 두면 느려지고 비싸지며, 이메일 하나 쓰는데 회계 규정까지 참고하게 됩니다.

해법

점진적 공개 — 평소에는 목차만 들고 있다가, 필요한 장(章)만 펴서 읽게 합니다. 스킬 폴더의 세부 파일은 참조될 때만 읽히므로, 무겁게 넣어도 평소에는 비용이 들지 않습니다.

9-2. 스킬 폴더의 구성

파일·폴더역할적는 것
SKILL.md (필수)진입점위쪽 머리말에 이름(name)과 설명(description), 아래에 실제 절차. 설명에는 "무엇을 하는지 + 언제 쓰는지" 둘 다 있어야 켜집니다
scripts실행 코드표 만들기, 파일 변환처럼 반복되는 처리
references참고 문서규정·기준표·예시 — 필요할 때만 읽힘
assets템플릿·글꼴·아이콘출력물에 쓰는 재료

이름 규칙 — 64자 이내, 소문자·숫자·하이픈만. 쓰는 법 — AI가 상황을 보고 알아서 부르며, "/스킬이름"으로 직접 부를 수도 있습니다.

실습 — 스킬을 만들어 주는 스킬(skill-creator)에게 시키기. 사이드바 "사용자 지정" → 스킬 → skill-creator를 켠 뒤 아래를 넣습니다.

/skill-creator
내가 매번 반복하는 {업무 — 예: 주간 보고서 작성}을 스킬로 만들고 싶어.
어떤 절차로 나눠야 할지 먼저 나에게 한 가지씩 질문해줘.
질문이 끝나면 SKILL.md의 이름·설명(무엇을 하는지 + 언제 쓰는지)과 절차를 제안해줘.

10. 커넥터 (Connectors) · MCP — AI를 내 메일·드라이브·노션과 잇기

AI는 학습한 지식으로 답할 뿐, 내 메일함이나 드라이브를 볼 수 없습니다. 이를 잇는 공통 규칙이 MCP(Model Context Protocol)이고, 클로드에서 그 규칙을 켜는 기능이 커넥터입니다. 구글(메일·캘린더·드라이브), 협업 도구(슬랙·노션 등), 깃허브·피그마·캔바 같은 커넥터가 미리 준비돼 있습니다.

10-1. 연결 전 보안 점검 — 비개발자용 네 가지

  1. 무엇을 연결하는가.
    연결은 앱 설치와 같습니다. 내 파일과 계정으로 통하는 문을 여는 것이니, 공식·검증된 것만. "편하니까 일단 다"가 가장 위험합니다.
  2. 무엇을 허용하는가.
    읽기만 줄지, 쓰기·삭제·전송까지 줄지가 핵심. 요약만 시킬 거면 읽기 전용으로 충분합니다. 승인 창이 뜨면 "왜 이 권한이 필요한지" 한 번 멈춥니다.
  3. 무엇을 노출하는가.
    연결한 폴더·메일은 전부 AI의 시야에 들어옵니다. 금융·계약·개인정보 자료는 연결 대상에서 뺍니다. 연결하지 않은 것은 새어 나갈 수 없습니다.
  4. 자동으로 할지, 확인할지.
    메일 전송·파일 삭제·결제·외부 공유는 자동화하지 않습니다. 메일은 "임시보관함 저장"까지만. 외부 글에 숨겨 둔 명령으로 AI를 조종하는 공격(프롬프트 인젝션)은 "확인 없이 실행"을 켜는 순간 통합니다.

실습 — 구글 드라이브 커넥터. 사용자 지정 → 커넥터 → 구글 드라이브 → 로그인·권한 확인 → 허용. 그다음 아래를 넣어 봅니다.

내 드라이브에서 가장 최근 문서를 찾아, 3줄로 요약하고 핵심 키워드 5개를 뽑아줘.
파일을 고치거나 옮기지는 말고 읽기만 해줘.

11. 딥 리서치 (Deep Research) — 출처가 달린 보고서를 AI가 대신 조사

일반 질문과 무엇이 다른가

일반 질문은 아는 것으로 바로 한마디(짧은 웹 검색 포함). 딥 리서치는 질문 하나로 계획을 세우고 → 웹을 수십 번 검색하고 → 문서를 열어 읽고 → 여러 출처를 맞대어 보고 → 각주·출처가 달린 한 편의 보고서를 씁니다.

시간이 걸립니다(도구에 따라 몇 분에서 30분). 채팅보다 사용량을 크게 씁니다. 완성된 보고서를 그대로 믿지 말고 사람이 최종 검토합니다.

실습 — 질문 설계 틀. 주제·범위·확실하지 않은 것 표시·출처 조건, 이 넷을 넣습니다.

{주제}에 대해 조사해줘.
범위: {기간·지역·대상 — 예: 2025년 이후, 국내, 소상공인 대상}
확실하지 않은 것은 "확인 필요"라고 표시해줘.
각 주장마다 출처를 달아 주고, 서로 다른 출처가 엇갈리면 그 사실도 적어줘.
결과는 요약 5줄 → 근거 → 상세 순서로 정리해줘.

받은 보고서에서 출처 두 개 이상을 직접 열어 확인한 뒤에 씁니다. 숫자·이름·날짜는 특히.
